# Design: DX: clangd LSP can't resolve test/plugin headers — no compilation database

- **Issue:** [#217 — DX: clangd LSP can't resolve test/plugin headers — no compilation database](../../../../issues/217)
- **Status:** Proposed

## 1. Summary

## Problem

The clangd language server reports a wall of spurious errors on every Objective-C file in this repo:

- `'XCTest/XCTest.h' file not found`
- `'AdiumY/<header>' file not found` (symlinked dir not on clangd's search path)
- `'AIUtilities/<header>' file not found` (framework headers)
- every `@interface X : NSObject` → `Cannot find interface declaration for 'NSObject'`
- cascading `expected type` / `undeclared identifier` errors

Root cause: clangd has no compilation database. The CoverageHost test target (and the plugin TUs it
compiles) need the SDK, `HEADER_SEARCH_PATHS` (`Tests/CoverageHost/AdiumY` symlink dir, the plugin
directories), `FRAMEWORK_SEARCH_PATHS` (the built AIUtilities.framework), and `-fobjc-arc` to
resolve anything. Without a `compile_commands.json`, clangd treats each file as a bare standalone TU.

This predates the current work — every existing UnitTests file shows the same noise.

## Proposed fix

Extend `Tests/CoverageHost/generate-xcodeproj.py` to also emit a `compile_commands.json` at repo
root (clangd's native database). The generator is the single source of truth for sources + header/
framework search paths + build flags, so the emitted database stays in sync with the real build.

Each entry: `{"directory": <repo root>, "command": <clang -x objective-c -fobjc-arc -F build/DerivedData/Build/Products/Debug -I Tests/CoverageHost/AdiumY -I ... -c <file> -o /dev/null>, "file": <abs path>}` for every UnitTests/ and plugin source the test target compiles.

Alternative quick unblock (no code): `xcodebuild -generateCompileCommands` once, then symlink/copy
the resulting JSON to `compile_commands.json` in the repo root (gitignore it). Less durable — a
stale database when the generator changes.

## Acceptance criteria

- Open any UnitTests file (e.g. `UnitTests/TestMenuPluginUninstall.m`) and any plugin .m in an
  editor with clangd: no red squiggles from unresolved SDK/AdiumY/AIUtilities headers.
- `compile_commands.json` is regenerated by the same script run that regenerates the xcodeproj.
